# packages/vector — exact-search demo harness

Dependency-free Node 22 harness for the synthetic demo fixture of the optional
pgvector retrieval path. It is **not** the production retriever: the backend
runtime (`backend/app/ai/vector_runtime.py`) and PostgreSQL functions in
`db/optional/` are authoritative.

What it checks without a database:

* exact cosine / L2 / inner-product distance over stored fixture vectors,
  including the real `1 - dot/(|a||b|)` cosine formula for non-unit queries;
* mandatory `workspaceId`/`language`/`framework`/`ruleFamily`/`status` filters;
* explicit spec compatibility: provider, model, version, metric, preparation
  and redaction versions compare exactly as in PostgreSQL (no case folding);
* `vetted` is refused: the fixture is draft-only;
* every returned item carries `sourceRef`, `redactedBefore`, `redactedFix`,
  `ruleVersion`, `verificationBasis`, `limitations` and `status`.

This harness still has no session/auth layer of its own: callers must pass a
workspace, and the backend binds that workspace to the authorized request scope
before any SQL runs. A matching string here is not an authorization check.

```bash
node packages/vector/verify-cli.mjs
node packages/vector/verify-cli.mjs db/optional/fixtures/vector_demo_examples.json
```

Fixture: [`db/optional/fixtures/vector_demo_examples.json`](../db/optional/fixtures/vector_demo_examples.json).
Storage and SQL function: [`db/optional/015_vector_demo_fixture.up.sql`](../db/optional/015_vector_demo_fixture.up.sql).
Seed/verify against PostgreSQL: `python -m backend.app.ai.vector_demo --seed` / `--verify`.

All five examples are `draft`, use `demo/fixture:` source refs, and carry the
16-dimension `synthetic-hashed-tokens` vectors generated by
`backend.app.ai.vector_demo.embed_text`. This is a lexical bucket sketch, not an
embedding model. Nothing here is vetted and nothing here demonstrates that
retrieval improves analysis.
