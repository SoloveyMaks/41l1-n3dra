## Собственная живая PG/ASGI проверка

Новый временный контейнер `sol-hook-review-pg`, pgvector:pg16, **network none**, Unix socket и данные только `/tmp/sol-hook-proof`; установленный Python venv. Одноразовые `proof.py`, `recover.py`, JSON и снимки в этой временной папке — локальное evidence, не переносимый комплект. Секреты случайные внутри процесса, не выводились и не передавались в argv. Middleware, маршруты, PostgreSQL, importer, intake и executor настоящие; HTTP провайдера в recovery подменён `httpx.MockTransport`, отдающим небольшой искусственный ZIP. Это synthetic callbacks и mocked provider, не живой push и не скачивание с GitHub/GitLab.

- Выполнен **владеющий v4 installer из db45c68**, записаны workflow/revision/watch, затем новый процесс с v5: версия5, прежний watch получил poll, workflow и revision сохранены. Core001–007 и старые runtime SQL в diff не изменены. Fresh/v2/v3 пути прочитаны, но отдельно заново мной не исполнялись.
- Чужой Origin: GET hook, POST hook/extra и POST setup получили403; точный POST hook проходит к provider auth без cookie. Non-ASCII GitHub signature и GitLab token дали401, подписанный неверный JSON400, тело1MiB+1 —413.
- Другой репозиторий, ветка, тег, удалённая ветка и paused watch дали ignored без создания запуска. Подпись проверяется до JSON. GitLab повтор одного тела с постоянным Webhook-UUID стал duplicate по digest; GitHub delivery повтор также duplicate.
- Шесть параллельных ASGI потоков: до освобождения тела вошли ровно **4** генератора. Подтверждён cap перед чтением; полные15s timeout и rate120/IP/min прочитаны в коде, отдельно не прожидались/не нагружались.
