# Словарь продукта и интерфейса

Один смысл — один русский термин. Английские и технические коды допустимы
только в раскрытии «Технические данные», а не в основной строке статуса.

Состояние на 21.11.2026. Роли `user`/`admin` уже реализованы в backend `dev`;
целевой frontend ещё в разработке, публичный стенд — на `9862e19`.

## 1. Основные термины

| Термин | Что значит | Не говорить | Пример |
| --- | --- | --- | --- |
| Проект | ZIP-архив Kotlin/Spring Boot, который проверяют | «репозиторий», если это не Git | «Загрузите ZIP-архив проекта» |
| Артефакт | Принятый ZIP с SHA-256 и манифестом, неизменяемый для проверок | «файл на диске» | «Артефакт выбран: sample_bank_app.zip» |
| Снимок проекта (snapshot) | Зафиксированное состояние файлов внутри артефакта | «архив» как синоним снимка | «Снимок проекта неизменяем после приёма» |
| Сценарий проверки (workflow) | Набор блоков и связей, который выполняет проверку | «воркфлоу» в тексте для жюри | «Сценарий проверки: Банковский аудит» |
| Черновик сценария | Редактируемая версия сценария | «draft» в основной строке | «Черновик сценария сохранён, граф валиден» |
| Проверка (run) | Одно выполнение сценария по одному артефакту | «запуск» как сущность | «Проверка завершена, вердикт: есть блокирующие проблемы» |
| Запустить проверку | Действие: начать выполнение сценария | «сделать run» | «Запустить проверку по готовому сценарию» |
| Блок | Узел сценария: триггер, анализатор, условие, отчёт | «нода» | «Блок Kotlin SAST завершён» |
| Связь | Направленное отношение между блоками или фактами | «edge» | «Связь: обработчик вызывает операцию» |
| Проблема (finding) | Обнаруженный статический дефект или риск; в API — `findings` | «находка», «баг» | «Проблема KOTLIN-SQL-INJECTION» |
| Доказательство (evidence) | Ссылка на файл, диапазон, хэш и фрагмент, подтверждающие проблему | «пруф» | «Доказательство: RepairLookupController.kt:12» |
| Фрагмент | Маскированная часть исходника, показанная по доказательству | «исходник целиком» | «Фрагмент исходника готов» |
| Маскировка | Удаление или замена секретных значений перед показом | «редакция» | «Redaction: cg-redaction/1» |
| Карта безопасности | Граф статических фактов кода: акторы, маршруты, обработчики, операции, данные | «граф выполнения» | «Карта доступа и данных» |
| Покрытие | Какие файлы, правила и зоны реально проверены | «полнота» без цифр | «Покрытие: частичное» |
| Вердикт | Итог политики: пройдено, есть блокирующие проблемы, недостаточно доказательств | «оценка» | «Вердикт: недостаточно доказательств» |
| Отчёт | Паспорт проверки, AI-объяснения и файлы JSON/Markdown | «документ» | «Скачать официальный JSON» |
| Сравнение | Сопоставление двух опубликованных проверок | «диф» | «Сравнение опубликованных проверок» |
| До/после | Baseline и current в сравнении | «старый/новый» без привязки к проверкам | «Baseline (до) → Current (после)» |
| Проверенный пример | Исправление, прошедшее реальный scanner provenance и проверку | «валидированный пример» | «Проверенных примеров: 0» |
| Черновик примера | Подготовленный пример без допуска `vetted` | «пример» без статуса | «3 примера — черновики» |
| Поиск похожих исправлений | Необязательный retrieval по базе исправлений | «память AI» | «Поиск похожих исправлений недоступен» |
| Векторные представления текста (embeddings) | Числовые представления текста для точного поиска; ANN-индекса нет | «векторный индекс», «эмбеддинги работают» | «Векторные представления недоступны: 403» |
| Ответ модели | Текст LLM, прошедший или не прошедший валидатор | «мнение AI» | «Ответ модели прошёл валидацию» |
| Fallback | Детерминированное объяснение, если модель недоступна **или** её ответ отклонён валидатором | «AI-ответ» | «Показан детерминированный fallback» |
| Политика | Правила доступа/владения для оценки связей | «policy» в основной строке | «Политика: допущение, не утверждено» |
| Пользователь (user) | Роль: загрузка, запуск проверки по готовому сценарию, чтение результатов | «аккаунт» | «Пользователь не меняет сценарий» |
| Администратор (admin) | Роль: операторские действия и обзор; отдельный код | «владелец тенанта» | «Администратор видит обзор» |
| Общий demo workspace | Одно пространство на всех, у кого есть код доступа | «аккаунт», «тенант» | «Данные стенда видны всем, у кого есть код» |
| Только просмотр | Экран не меняет факты и настройки | «редактирование» | «Проблемы и отчёт — только просмотр» |

## 2. Роли и доступ

| Что | Пользователь | Администратор |
| --- | ---: | ---: |
| Вход | `CG_ACCESS_CODE` | `CG_ADMIN_ACCESS_CODE` |
| Загрузка ZIP/sample | да | да |
| Чтение проверок, проблем, карты, доказательств, отчёта, сравнений | да | да |
| Запустить проверку по существующему сценарию | да | да |
| Валидация и типы блоков | да, только чтение | да |
| Создание сценария / `PUT draft` | 403 | да |
| Расписания | 403 | да |
| AI-тест (synthetic-test) | 403 | да |
| Training-проект | 403 | да |
| Логи webhook-теста | 403 | да |
| `GET /api/admin/overview` | 403 | да |

Роли — подписанное ограничение операторских действий поверх одного workspace,
а не аккаунты, списки доступа или изоляция данных. `adminAvailable: false`, если admin-код не задан или совпадает
с пользовательским; тогда admin-вход возвращает 503, а user-вход работает.

## 3. Статусы: как писать по-русски

### Проверка

| Код | Русский статус | Что значит |
| --- | --- | --- |
| `queued` | В очереди | Проверка принята, выполнение не началось |
| `running` | Выполняется | Блоки ещё работают |
| `succeeded` | Завершена | Выполнение дошло до конца |
| `failed` | Ошибка | Выполнение прервано ошибкой |
| `interrupted` | Прервана | Выполнение остановлено извне |
| `cancelled` | Отменена | Проверка отменена |

### Вердикт

| Код | Русский статус | Честный смысл |
| --- | --- | --- |
| `pass` | Проверка пройдена | Нет блокирующих проблем по политике при данном покрытии; низкие и допустимые средние проблемы могут остаться |
| `fail` | Есть блокирующие проблемы | Порог политики превышен |
| `inconclusive` | Недостаточно доказательств | Покрытие неполное или анализ не дал уверенного ответа |
| `pending` | Ещё не посчитан | Вердикта пока нет |

`pass` — это не «ноль проблем» и не «безопасно». Это «нет блокирующих по
политике» при текущем покрытии.

### Проблема

| Код | Русский статус | Что значит |
| --- | --- | --- |
| `confirmed` | Подтверждена | Статический паттерн подтверждён; это не эксплуатация |
| `potential` | Потенциальная | Нужен контекст, которого нет в статике |
| `inconclusive` | Не подтверждена | Данных недостаточно |

Серьёзность: `critical` → «критическая», `high` → «высокая», `medium` →
«средняя», `low` → «низкая», `info` → «информационная».

### Сравнение

| Код | Русский статус | Честный смысл |
| --- | --- | --- |
| `persistent` | Остаётся | Проблема есть в обеих проверках |
| `introduced` | Появилась | В «после» появилась новая проблема |
| `changed` | Изменилась | Тот же anchor, но изменились контекст/детали |
| `resolved` | Исправлена | Паттерн исчез при сопоставимой проверке |
| `inconclusive` | Не подтверждено | Покрытие или anchor не позволяют утверждать |
| `file_deleted` | Файл удалён | Удаление файла, а не доказательство исправления |

SQL-статусы: `pattern_disappeared` → «Паттерн исчез при сопоставимой проверке»;
`persistent` → «Паттерн сохраняется»; `changed` → «Паттерн изменился».

### Покрытие и карта

| Код/состояние | Русский статус | Что значит |
| --- | --- | --- |
| `complete` | Полная картина | Все ожидаемые зоны проверены |
| `partial` | Частичная картина | Есть пробелы; это не «почти безопасно» |
| `resolved` (связь) | Связь разрешена | Статическая связь установлена; не «исправлено» |
| `partial` (связь) | Связь частичная | Связь видна, но доказательств мало |
| `unknown` (связь) | Связь неизвестна | Пробел анализа, а не безопасное состояние |
| `assumption` (политика) | Допущение — не утверждено | Правило не подтверждено владельцем |

### AI и векторные представления

| Код | Русский статус | Что значит |
| --- | --- | --- |
| `succeeded` | Прошёл валидацию | Ответ модели проверен по проблеме/CVE |
| `fallback` | Детерминированное объяснение | Модель недоступна или её ответ отклонён валидатором; факты не изменены |
| `unavailable` | Недоступно | Провайдер или функция не отвечает |
| `disabled` | Выключено | Функция не включена |
| `pending` | Ожидает | Ещё не выбрано/не подтверждено |

Векторные представления текста: `disabled` → «Выключены»; `unavailable` →
«Недоступны» (реальный запрос вернул 403); `activeEmbeddingSpecs: 0` → «Активных
спек: 0». Точный поиск задуман без ANN-индекса; fake active не показывать.

## 4. Честные формулировки

Готовые фразы, которые не усиливают результат:

- «Проверка пройдена: блокирующих проблем нет. Низкие и допустимые средние
  проблемы могут остаться».
- «Подтверждённая проблема — это статический паттерн, а не доказанная
  эксплуатация».
- «В паспорте есть проверенные и пропущенные файлы. Полное покрытие не
  заявляется».
- «Карта частичная: 4 неизвестные связи. Жёлтый пунктир — пробел анализа, а не
  безопасное состояние».
- «Связь актор → маршрут неизвестна: нет применимого статического правила
  авторизации, runtime-конфигурация неизвестна».
- «Сравнение вернуло `inconclusive`: потеряно проверенное покрытие. Исправление
  не подтверждено».
- «Файл удалён. Это не доказательство исправления».
- «Паттерн SQL исчез при сопоставимой проверке. Это узкая проверка одного
  правила, не общий вердикт».
- «Исходник недоступен (`source_unavailable`). Фрагмент не показан, повтор
  запроса доступен».
- «Fallback: модель недоступна или ответ отклонён валидатором. Проблемы,
  покрытие и вердикт не изменились».
- «Векторные представления текста недоступны: 403. Точный поиск без
  ANN-индекса, активных спек 0, проверенных примеров 0; три подготовленных —
  черновики».
- «Демо-сценарий — это черновик сценария, а не накопленный опыт и не
  доказательство качества».

## 5. Раскрытие технических деталей

Правило: **сначала человеческий результат, потом причина, потом техника**.
Техника не исчезает — она уходит в раскрываемый блок.

Порядок на экране:

1. Статус: «Недостаточно доказательств».
2. Причина: «Не отработали сканеры: sast; 2 ошибки парсера».
3. `details` → «Технические данные»: сырые значения, покрытие, версии, hashes.

Что держать на виду:

- путь и строка проблемы;
- правило и серьёзность;
- вердикт и статус покрытия;
- статус сравнения и причина;
- явная недоступность данных.

Что убирать в «Технические данные»:

- UUID workspace/проверки/снимка;
- SHA-256 и версии producer/redaction;
- сырые JSON-входы и выходы блоков;
- сырые enum-коды (`INCONCLUSIVE`, `file_deleted`, `fallback`);
- внутренние идентификаторы доказательств и узлов.

Что нельзя скрывать в `details`:

- сам факт неизвестности или неполноты;
- причину `inconclusive`;
- ошибку загрузки исходника;
- отсутствие AI или векторных представлений;
- `pass` при неполном покрытии.

Пример раскрытия:

```text
Вердикт: Недостаточно доказательств
Причина: не отработали сканеры: sast; 2 ошибки парсера
  ▸ Технические данные
    coverage.status = partial
    missing scanners = sast
    parserErrors = 2
    signature.rulesHash = <hash>
```

Секреты: сырое значение не показывается никогда. Только маскированный
фрагмент, `sourceHash`, диапазон байтов и версия redaction. Если маскировка
неполная — статус `source_redaction_incomplete`, а не «всё хорошо».

## 7. Статусы, которые нельзя смягчать

| Нельзя | Почему |
| --- | --- |
| `pass` → «проблем нет» | Проблемы ниже порога могут остаться |
| `fail` → «есть замечания» | Это блокирующий вердикт, а не заметка |
| `inconclusive` → «ок» | Это отсутствие доказательств, а не успех |
| `unavailable` → «пусто» | Это сбой или отключение, а не отсутствие данных |
| 0 проблем → «безопасно» | Нулевой результат без покрытия ничего не доказывает |
| `partial` → «полно» | Потеря покрытия остаётся видимой |
| `file_deleted` → «исправлено» | Удаление файла не доказывает исправление |
| `pattern_disappeared` → «уязвимостей нет» | Проверено одно правило на одном паттерне |
| `fallback` → «модель всегда недоступна» | Fallback бывает и при отказе валидатора |

## 9. Границы словаря

- Роли `user`/`admin` уже есть в backend `dev`; словарь не выдаёт их за
  аккаунты, списки доступа или multi-tenant.
- Целевой админский frontend ещё в разработке; публичный стенд на `9862e19`
  старый.
- Векторные представления текста — точный поиск без ANN-индекса; сейчас 403,
  активных спек 0.
- Проверенных примеров 0; три подготовленных — черновики.
- Словарь не переименовывает API-поля и SQL: `runId`, `baselineRunId`,
  `security_verdict`, `findings` остаются техническими идентификаторами.
- Точные значения полей — в [data-contracts](data-contracts/README.md).
