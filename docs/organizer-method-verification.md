## Уточнение сверки SCA

`analyzers.compare` теперь требует совпадения категории, пути, group, artifact,
версии и advisoryId из списка допустимых идентификаторов эталона.
Для SECRET/SAST сверяются категория, путь, класс и пересечение диапазонов строк.
Одно срабатывание не засчитывается сразу двум эталонным случаям.
Одноразовая проверка показала: подмена версии и подмена пути у каждой из пяти
SCA-находок отклоняются; настоящие результаты по-прежнему дают 15/15.
Для безопасного SCA-примера учитываются путь, координаты и версия, если она задана.

## Два формата отчёта

Отдельно выполнен прямой объединённый анализ backend + Team B, без запуска
веб-сервера или проверяемого приложения: SECRET=5, SCA=5, SAST=5.
Его единый список передан штатному `ReportBuilder`. В официальном JSON и
читаемом Markdown ровно по 15 находок; множества ID с учётом повторений совпали.
В отчёте сохранено частичное покрытие. ИИ-проверка в этот прогон не включалась.
Это проверка генератора отчётов, а не повторная проверка скачивания файлов в UI.

В полном workflow может дополнительно появиться неподтверждённая запись codefacts
по отсутствующему owner-check. Её нельзя объявлять отдельной доказанной
шестнадцатой уязвимостью поверх 15 эталонных случаев.

## Повторение

```bash
python -m analyzers.scan "$SNAPSHOT/training-project" \
  --db "$SNAPSHOT/vulnerability-database/vulnerabilities.json" \
  --out /tmp/submission.json --full /tmp/scan-full.json
python -m analyzers.compare /tmp/submission.json \
  --truth "$SNAPSHOT/ground-truth/training-findings.json" \
  --out /tmp/comparison.json
```

Локальные артефакты текущего прогона: `/tmp/nedra-mentor-submission.json`,
`/tmp/nedra-mentor-comparison-strict.json`, `/tmp/nedra-mentor-unified.json`,
`/tmp/nedra-mentor-unified.md`, `/tmp/nedra-mentor-method-proof.json`.
Они временные и в репозиторий не включены.
