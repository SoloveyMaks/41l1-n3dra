# Интерфейс: пользователь и администратор

Пользовательский экран и админка разведены по ролям. Обычный посетитель сразу
попадает в редактор своей проверки и собирает сценарий из блоков. Админка
остаётся отдельным shell-ом с боковой навигацией и системными панелями.

## Пользователь

Главный экран — прежняя панель с горизонтальной навигацией `Navbar`, а не
статичная форма из трёх карточек. Первой открывается вкладка «Редактор»:

- **Сценарий** — выбор в верхней панели канваса; кнопка «Новый» создаёт
  именованную копию текущих блоков и связей, не перезаписывая стандартный
  сценарий. Выбранный id запоминается в localStorage.
- **Проект** — кнопка «ZIP или репозиторий» в `Navbar`; источник с веткой и
  коротким SHA показан рядом с выбором проекта на канвасе.
- **Блоки** — `NodePalette` добавляет узлы, `WorkflowCanvas` соединяет их,
  `InspectorPanel` настраивает название и параметры. «Сохранить draft» пишет
  черновик через `PUT /workflows/{id}/draft`.
- **Запуск** — кнопка «Запустить проверку» сохраняет актуальный draft и запускает
  выбранный сценарий. Открывается вкладка «Ход проверки».

Вкладки `Navbar`: «Редактор», «Ход проверки», «Проблемы», «Карта доступа»,
«Отчёт», «Сравнение». История запусков находится в селекте `Navbar` и
фильтруется по выбранному `workflow_id`; стандартный `wf_secure_pr_gate` не
подставляется в историю пользователя. При перезагрузке стартовый запуск также
берётся только из выбранного сценария; если запусков нет, текущий запуск,
отчёт, findings и SSE очищаются — результат другого сценария не показывается.
После завершения проверки доступны проблемы, карта, отчёт и сравнение.

Пользователь не видит вкладку «Автозапуск», кнопку «Тест AI» и админский shell.
Его сессия не обращается к `/api/admin/*`, `/api/schedules`,
`/api/repository-watches`; эти API остаются административными и отвечают `403`.
Создание сценария и сохранение draft используют только аутентифицированную
сессию общего workspace.

Словарь: `findings` — «Проблемы», `evidence` — «Фрагмент кода/Доказательство»,
`workflow` — «Сценарий проверки», `snapshot` — «Снимок проекта», `run` —
«Проверка», `pass` — «Нет блокирующих проблем по политике» (если findings > 0) или
  «Проблем не выявлено в проверенной части» (если findings = 0), `fail` —
«Найдены проблемы», `inconclusive` — «Неполная проверка».

## Администратор

Отдельный `AdminShell` с группами:

- **Обзор** — реальные счётчики, последняя проверка, состояние DB/model/vector.
- **Проекты и проверки** — проекты и история, переход в результаты.
- **Сценарий** — существующий конструктор и автозапуск: архив по расписанию,
  проверка репозитория по таймеру и доставка по пушу (webhook). В режиме пуша
  показываются адрес доставки, секрет в маске с копированием, шаги для
  GitHub/GitLab, предупреждение о перевыпуске и честная пометка, что хук в
  репозитории ставится вручную.
- **Результаты** — ход проверки, проблемы, карта, отчёт, сравнение.
- **Система** — анализаторы/покрытие (readonly), AI и память исправлений,
  доступ и состояние без секретов.

Обзор использует `GET /api/admin/overview` (реальный DTO: `counts`, `db`, `ai`,
`vector`, `uploads`, `workspace`, `auth`). Если endpoint недоступен, панель
показывает реальные локальные счётчики и явно пишет, что DTO не отдан.

## Access gate

- По умолчанию — вход обычного пользователя по `CG_ACCESS_CODE`.
- Ссылка «Вход для администратора» открывает отдельную форму.
- `POST /api/session` получает `{ accessCode, role: "user" | "admin" }`.
- Админ-код — отдельный `CG_ADMIN_ACCESS_CODE`; `adminAvailable` приходит в
  `/api/session`. Админ-вход не повышает права обычным кодом.

## Компоненты

- `Navbar.tsx` — прежняя горизонтальная панель: вкладки, история,
  ZIP/репозиторий и запуск.
- `ScenarioCreateModal.tsx` — именованный сценарий из текущих блоков.
- `WorkflowCanvas.tsx`, `NodePalette.tsx`, `InspectorPanel.tsx`,
  `CustomNode.tsx` — общий редактор для пользователя и админки.
- `AdminShell.tsx` — боковая навигация и каркас админки.
- `AdminPanels.tsx` — обзор, проекты, анализаторы, AI, доступ.
- `AccessGate.tsx` — user/admin вход.
- `UserDashboard.tsx` — legacy-компонент быстрого режима; в основном потоке не
  смонтирован.

`SecurityMapScreen.tsx` и `ui/security-map/**` не изменялись — это зона
map-worker. Backend-модули импорта, наблюдений и атомарного старта подключены
merge-коммитами владельцев; интерфейс backend-файлы не правит.

## Admin overview freshness

`GET /api/admin/overview` is fetched only for an admin session: on role entry,
after a manual run-history refresh, and after a new run reaches terminal state
(including polling fallback). Node-level SSE events do not refresh it. Responses are auth-epoch/sequence-guarded; logout/role changes invalidate them, and a failed refresh
clears stale counters instead of showing them as current. Refreshing workspace
counts never changes the selected run.

## Ограничения

- Нет выдуманных пользователей/CRUD: админка показывает только реальные
  artifacts/workflows/runs/schedules и фактические DTO.
- AI-поиск исправлений не изображается; показывается фактический `ai_status`
  отчёта.
- Технические ID запуска и SSE остаются в «Ходе проверки» для отладки; редактор
  и основные действия подписаны по-русски.
- Секреты не выводятся: gate принимает код, env/ключи не попадают в UI или argv.
