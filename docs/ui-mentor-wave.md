# UI-волна для показа: живой запуск, проблемы, палитра, карта

Дата: 21.11.2026. Работа во `frontend/**` и этом файле. Backend-контракты
аккаунтов и AI-сканера взяты из `dev` merge-коммитом; сам backend, API, схемы,
`ui/security-map/**`, Telegram и экспорт отчёта в этой волне не правились.

## 1. «Ход проверки»: этапы вместо трёх колонок

`frontend/src/components/LiveRunView.tsx` перестроен в читаемую ленту этапов.

- Слева — карточки этапов, сгруппированные по смыслу:
  1. снимок проекта и триггер;
  2. сканеры SECRET/SCA/SAST;
  3. факты кода и карта доступа;
  4. политика и ветвление;
  5. AI-объяснение;
  6. отчёт и паспорт;
  7. уведомление.
- Справа — детали выбранного блока: входные/выходные замаскированные данные и
  поток SSE. В потоке можно оставить только события выбранного блока.
- Статусы берутся из `node_runs` и SSE, без искусственного прогресса:
  `queued`/`running`/`succeeded`/`failed`/`skipped`, плюс `cancelled`.
- Для уведомления показывается фактический `delivery_result.status`:
  `skipped` не маскируется под успешное выполнение блока.
- Длительность: `duration_ms` блока; для запуска — от `started_at` до
  `finished_at`, а у активного запуска — до текущего времени.
- Короткий результат зависит от типа блока:
  - сканер — число находок, файлов, правил, диагностика, разбивка по риску;
  - слияние — находки, файлы, CF-правила, ошибки парсера, неразрешённые
    зависимости, предупреждение о недоступной карте;
  - политика — вердикт и причина;
  - AI — статус, модель, число объяснений и краткий summary;
  - отчёт — вердикт, число находок, файлы/строки, время сборки;
  - уведомление — статус доставки, канал и сообщение.
- Блок, который уже стартовал по SSE (`node_status: running`), но ещё не попал
  в `node_runs`, показывается как выполняющийся. Это реальное событие, а не
  выдуманный процент: после завершения его заменяет запись `node_runs`.
- У завершённого запуска неисполненные блоки не дорисовываются: показываются
  только реальные записи и реальные SSE-события. Поэтому нет фальшивых
  «ожидающих» карточек для веток, которые не выполнялись.

Навигация из карточек: «Открыть проблемы», «Открыть карту доступа»,
«Открыть отчёт». В пользовательском режиме это вкладки, в админке — разделы
результатов.

## 2. «Проблемы»: сортировка по умолчанию

`frontend/src/components/FindingsView.tsx`.

- По умолчанию: `critical → high → medium → low → info`.
- Внутри одного риска: `confirmed → potential → inconclusive`.
- Детерминированный добор: путь, начальная строка, колонка, `ruleId`, `id`.
  Сравнение строк посимвольное, без зависимости от локали браузера.
- Фильтры по анализатору, риску и поиску применяются до сортировки и не
  сбрасываются при переключении порядка. Добавлен фильтр «Инфо» и счётчики
  низкого/информационного риска.
- Ручной режим «По файлу и строке» оставляет тот же детерминированный добор.
- Бейджи риска раскрашены для всех пяти уровней.

## 3. Сворачиваемая палитра блоков

`frontend/src/components/NodePalette.tsx`.

- Кнопка сворачивания/разворачивания в заголовке палитры.
- На десктопе свёрнутое состояние — узкая полоса с вертикальной подписью и
  числом блоков; на мобильном остаётся компактная строка заголовка.
- Выбор хранится в `localStorage` под ключом `nedra.nodePaletteCollapsed`
  (`'1'` — свёрнуто, `'0'` — развёрнуто) и восстанавливается после перезагрузки.
- При недоступном `localStorage` палитра продолжает работать в текущей сессии.

## 4. Карта доступа: только интеграционные состояния

`frontend/src/components/SecurityMapScreen.tsx`. Готовый граф по-прежнему
рисует `ui/security-map/**`; этот пакет не изменялся, новая модель графа не
вводилась.

- Нет выбранного запуска — русское объяснение, что карта строится по снимку
  запуска и где выбрать запуск.
- Загрузка — скелетон в стиле приложения, короткий id запуска и честная
  подпись, что карта ждёт факты кода и доказательства от сервера.
- Ошибка — человеческая причина (`source_unavailable` или общий отказ),
  короткий id, код и кнопка повторной загрузки.
- Этап «Факты кода и карта доступа» в «Ходе проверки» показывает CF-правила,
  диагностику и предупреждение, если карта не построена, и ведёт на вкладку
  карты.

## 5. Аккаунты, профиль и история

`AccessGate.tsx`, `AccountModal.tsx`, `Navbar.tsx`, `App.tsx`,
`api/client.ts`, `types/index.ts`.

- Вход по email/паролю и открытая регистрация с именем; если backend отдал
  `registrationInviteRequired`, появляется поле кода приглашения.
- Demo-вход по коду организатора и админ-вход остаются отдельными явными
  режимами. Demo не называется личным профилем.
- После входа Navbar показывает имя аккаунта; кнопка открывает модалку с
  email, сводкой профиля (`runs`, `totalFindings`, ошибки, последний запуск) и
  личной историей `GET /api/auth/history`.
- История кликабельна и открывает соответствующий запуск; при demo-сессии
  показывается честная пометка общего workspace, профиль берётся из
  `/api/profile` только для account-сессии (`DEMO_SESSION` не маскируется).
- Logout отзывает сессию, очищает выбранный запуск/AI-гипотезы и возвращает
  экран входа; повторный вход снова загружает редактор. Выбранный workflow
  восстанавливается из `localStorage`, как раньше.

## 6. AI-сканер: отдельные гипотезы

`NodePalette.tsx`, `CustomNode.tsx`, `InspectorPanel.tsx`, `LiveRunView.tsx`,
`FindingsView.tsx`, `AiHypothesesPanel.tsx`, `types/index.ts`.

- В палитру добавлен блок `ai_scan` с портами `artifact` + необязательный
  `findings_bundle` и выходом `ai_scan_result`.
- Инспектор настраивает только бюджет: `profile`, `maxFiles`, `maxBytes`,
  `perFileBytes`, `maxObservations`. Модель, URL и ключ задаются сервером и в
  UI не вводятся.
- «Ход проверки» показывает отдельный этап «AI-гипотезы»: статус, число
  гипотез, покрытие, отправленные файлы, подавленные дубли и деградацию.
- «Проблемы» показывают отдельную секцию «AI-гипотезы» над подтверждёнными
  findings: статус, ограничения покрытия, источник/модель, severity, правило,
  файл, rationale, redacted-фрагмент, remediation и grounding.
- Секция явно помечена «не findings · не влияет на вердикт». Гипотезы не
  добавляются в счётчик проблем, не меняют вердикт, отчёт или policy.
  `/runs/{id}/evidence/{id}` для `aiobs_*` не вызывается.

## Ограничения

- Нет отдельного серверного статуса «queued» для каждого ещё не начатого блока:
  такие карточки не рисуются. `queued` показывается на уровне запуска и для
  записей со статусом `pending`.
- Карточки строятся по текущему draft только для распознавания типа уже
  стартовавшего блока по SSE. Если черновик изменили во время запуска, тип
  может быть определён по id-подсказке; данные и статус всё равно берутся из
  реальных событий/записей.
- Готовый граф карты, его раскладка и доказательства остаются зоной
  `ui/security-map/**`; здесь улучшены только загрузка, ошибка и пустое
  состояние интеграционного экрана.
- Demo-сессия остаётся общим workspace без личного профиля; счётчики профиля
  для неё не подделываются. Per-user schedules/watches по-прежнему вне этой
  UI-волны.
- AI-гипотезы ограничены выбранным redacted-фрагментом и бюджетом; `partial`
  или `degraded` не доказывают отсутствие проблем. Гипотезы никогда не
  смешиваются с findings и не меняют вердикт/отчёт.
- Telegram, экспорт отчёта и `ui/security-map/**` не затрагивались.
