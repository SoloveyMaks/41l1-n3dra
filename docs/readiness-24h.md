## Правила приёмки

1. Коммит и наличие блока в палитре сами по себе не означают готовность.
2. Факты анализаторов, гипотезы ИИ и пользовательская политика остаются разными данными.
3. Проверка аккаунтов включает workflow, artifacts, runs, evidence, reports и фоновые задачи.
4. Публикация идёт законченными частями после живой проверки, с резервной копией БД
   перед миграциями и сохранением предыдущего образа.
5. Отказ embeddings или внешнего ИИ не ломает основной анализ.
6. Токены и пароли не попадают в сценарии, отчёты, журналы и git.

- ReformBoss проверен живым запросом: HTTP 200, валидный JSON,
  `deepseek-v4.1-flash-1017`; проверка не доказывает качество анализа.
- Telegram: токен добавлен в приватную runtime-конфигурацию вне git, права 600.
  `getMe` подтвердил бота `@chilli_nedra_bot` через существующий HTTP-прокси.
  Приём задач и доставка результатов реализованы локально; найденные ошибки перепривязки, отмены и recovery исправлены и приняты независимым Sol review. Из production-контейнера существующий loopback-прокси недоступен; подготовлен и проверен scoped UNIX-сокет-маршрут, но в production он ещё не включён — нужен root-wiring. Подробности: [Telegram deployment](telegram-deployment.md). Значения секретов в документацию не включаются.
- Голосовой ввод использует SpeechRecognition браузера по нажатию; при отсутствии поддержки доступен текст. Браузер может использовать свой внешний сервис распознавания. Реальная диктовка и разрешение микрофона в production ещё не подтверждены.

## Проверка объединённой версии

После merge аккаунтов, AI_SCAN, UI, Telegram и per-user triggers выполнен
реальный ASGI-прогон на временной PostgreSQL. Два обычных аккаунта изолированы,
свои schedules/watches возвращают 200, admin overview — 403, чужой workflow — 404.
Telegram binding возвращает одноразовый код TTL600, список сценариев изолирован;
после logout старый cookie даёт 401. Миграции 008/009/010/011/012 есть в ledger; повторное применение вернуло пустой список.
Опрос Telegram выключен в проверке явно, реальные сообщения не отправлялись.
Frontend build успешен: `index-B3Aajpfu.js`, стили `index-D71FWbKK.css`.
Скачивание DOCX и JSONC проверено под обычным аккаунтом (200), чужой аккаунт
получает 404; пустой запуск явно сообщает `reportAvailable=false`, DOCX открывается
через python-docx. Это проверка маршрутов и изоляции, а не повтор визуального просмотра.

Независимый Sol review принял исправления Telegram на точных SHA
`024c300` и `4ab9621`: исходное зависание, утечка guard connection при отмене,
ограничение общего recovery batch и fencing проверены на реальной PG.
Внешняя Telegram-доставка в чат по-прежнему не подтверждена.
[Sol review](reviews/sol-accounts-telegram.md).

Экспорт DOCX визуально проверен по всем восьми PNG после `a08fb6a`:
таблицы, ссылки и перенос цепочек читаемы, отдельной почти пустой страницы
с последним пунктом больше нет.

Генератор сценариев подключён к API и кнопке «По описанию» в обоих редакторах.
Preview/apply не сохраняют и не запускают workflow; текущее artifactId переносится
в project_input, выбранный старый run сбрасывается. Сервис проверен настоящим
ReformBoss владельцем компонента, ошибка провайдера даёт 503, короткий prompt —
400, запрос без сессии — 401. Root проверил API основного приложения с явным
локальным недоступным endpoint и синтетическим ключом: `AI_PROVIDER=disabled`
не является выключателем текущего provider resolver и сам по себе этого не
гарантирует. После проверки список сохранённых workflow не меняется.

Подсказка ответственности подключена к основному приложению: свой endpoint 200,
чужой или отсутствующая находка 404; сохранённые факты анализатора не меняются.
История содержит last-file commit author/committer, связанный PR, merge и review.
`864273d` разделяет решение и комментарий, помечает неполную историю и явно
указывает association SHA; `2af8c391` заменяет regex CODEOWNERS на ограниченный
полиномиальный matcher и выносит синхронные чтения из event loop. Независимая
повторная приёмка идёт; дополнительное ограничение очереди и реального времени
жизни worker thread передано владельцу. Это пока не принятый production-блок.
[Responsibility review](reviews/sol-responsibility.md).

Все перечисленные изменения остаются локальными в dev и не описывают текущий
