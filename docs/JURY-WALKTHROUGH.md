# Сценарий показа для жюри

Короткий проход по продукту и честное разделение трёх состояний. Это не
production-обещание.

Состояние на 21.11.2026.

## Три состояния, которые нельзя смешивать

| Состояние | Ревизия/статус | Что там реально есть | Что показывать |
| --- | --- | --- | --- |
| Публичный стенд | `9862e19` | Старый интерфейс: один общий код, редактор с `PUT draft`, без ролей и админки | Только старый маршрут из примечания ниже |
| Backend `dev` | `5e36d4f`, роли с `4012fb5` | Роли `user`/`admin`, `GET /api/admin/overview`, отдельный admin-код в bootstrap; frontend ещё старый | API-контракт и права; не выдавать backend за готовый frontend |
| Целевой frontend | Отдельная разработка, не опубликован | Простой user-путь без редактора и админские разделы | Только после мержа и проверки; не показывать как опубликованное |

Главный walkthrough ниже — **целевой user-путь**. Backend-права для него уже
готовы, но разделение интерфейса ещё не в опубликованной сборке. На публичном стенде
`9862e19` и в текущем frontend `dev` старый редактор делает `PUT draft`, поэтому
роль `user` там не показывает новый простой путь.

## Главное за 30 секунд

- Пользователь выбирает ZIP или демо, запускает **существующий сценарий
  проверки** и смотрит результаты. Редактор, сохранение draft, расписания,
  AI-тест и training — не пользовательские действия.
- Администратор входит отдельным кодом и видит операторский обзор. Это не
  личный кабинет и не отдельный tenant.
- `user`/`admin` — подписанные в сессии роли поверх **одного общего
  workspace**. Аккаунтов, списков доступа и изоляции данных между
  пользователями нет.
- `pass` не означает «ноль проблем»: это отсутствие блокирующих проблем по
  политике при текущем покрытии. Низкие и допустимые средние проблемы могут
  остаться.
- Векторные представления текста сейчас недоступны: реальный
  `/v1/embeddings` вернул 403. Точный поиск задуман без ANN-индекса; активных
  спек 0, fake active нет.
- Проверенных примеров исправления 0; подготовленные примеры — черновики, не
  опыт.

## Целевой user-путь

Предусловие: разделение интерфейса смержено и проверено; backend `dev` с ролями; выдан
пользовательский код.

### 1. Вход пользователем

Действие: открыть стенд, ввести пользовательский код.

Что происходит:

- создаётся сессия с `role: "user"`;
- `adminAvailable` может быть `true`, но это не даёт прав администратора;
- workspace общий: данные видны всем, у кого есть пользовательский код.

Говорить:

> Роль — это подписанное ограничение операторских действий, а не аккаунт.
> Отдельных кабинетов и изоляции клиентов нет.

Не утверждать: «личный кабинет», «списки доступа», «multi-tenant».

### 2. Выбрать ZIP или демо

Действие: загрузить `.zip` или нажать «Загрузить sample (Kotlin/Spring Boot)».

Что реально проверяется:

- только `.zip`, до 50 MB;
- защита от path traversal и zip-бомб;
- манифест: имя, SHA-256, размер, число файлов, `.kt` и Gradle-файлов;
- sample — учебный банковский проект с SQL-инъекцией, path traversal, command
  injection и секретами в конфиге.

Пользователь может загружать артефакты и читать их список. Training-project —
только admin: у `user` `POST /artifacts/sample/training` даёт 403.

Говорить:

> Архив становится неизменяемым артефактом. Дальше проверка идёт по снимку
> проекта, а не по живой папке.

### 3. Запустить существующий сценарий проверки

Действие: выбрать готовый **сценарий проверки** и нажать «Запустить». Артефакт
передаётся в запросе.

Чего здесь нет:

- нет редактора графа;
- нет `PUT /workflows/{id}/draft`;
- нет создания сценария и расписаний;
- нет AI-теста и training.

Почему так: `user` не может менять сценарий. Backend берёт уже сохранённый
draft и его ревизию, а `POST /workflows/{id}/runs` только создаёт проверку.
Если пользовательский экран предлагает «Сохранить draft» — это баг frontend.

Что видно:

- сценарий по умолчанию: 11 блоков и 13 связей;
- статусы блоков, длительность, маскированные входы/выходы, SSE-события;
- вердикт и число проблем в шапке проверки.

Говорить:

> Пользователь запускает проверку по готовому сценарию. Менять сценарий может
> только администратор.

### 4. Проблемы и фрагмент

Действие: открыть раздел «Проблемы» → выбрать проблему (например,
`KOTLIN-SQL-INJECTION`) → посмотреть карточку и маскированный фрагмент.

Что видно:

- серьёзность и обоснование риска;
- уверенность и её обоснование;
- путь и строка;
- маскированный фрагмент кода;
- цепочка шагов `trace`;
- advisory/CVE, если есть;
- AI-рекомендация, если AI отработал.

Говорить:

> «Подтверждённая» проблема — это подтверждённый статический паттерн, а не
> доказанная эксплуатация. Секреты маскируются.

Не утверждать: «взломали приложение» или «это работает в runtime». Runtime не
запускается.

### 5. Карта и цепочка

Действие: открыть «Карту безопасности» → выбрать проблему или узел → нажать
«Показать путь».

Что видно:

- узлы: «Актор», «Маршрут», «Guard», «Обработчик», «Операция», «Данные»,
  «Конфиг»;
- связи: маршрут, вызов, передача, чтение/запись, защита;
- счётчики узлов, связей, проблем и доказательств;
- жёлтый пунктир и баннер «Неизвестные или частичные связи»;
- покрытие «полная картина» или «частичная картина».

Говорить:

> Карта — это статические факты кода и доказательства, а не граф выполнения
> сценария. Жёлтый пунктир — пробел анализа, а не безопасное состояние.

Не утверждать: «все связи известны» или «полное покрытие», если есть
unknown/partial.

### 6. Сравнить SQL до/после

Есть два честных варианта.

**Вариант A, если подготовлены две проверки.** Загрузить `before.zip` и
`after.zip` из `examples/demo/sql-before-after/`, выполнить каждую, дождаться
завершения, затем открыть «Сравнение», выбрать **Baseline (до)** и
**Current (после)** и нажать «Сравнить».

**Вариант B, если готовых пар нет.** Сравнить две любые завершённые проверки.
Отдельный блок «Проверка SQL-паттерна» появится только при подходящих данных,
иначе покажет «Отдельная проверка недоступна».

Что видно:

- «Сравнение сопоставимо» или «Недостаточно доказательств: исправление не
  подтверждено»;
- статусы: «Остаётся», «Появилась», «Изменилась», «Исправлена», «Не
  подтверждено», «Файл удалён»;
- отдельный блок: «Паттерн исчез при сопоставимой проверке»;
- удалённые файлы вынесены отдельно.

Говорить:

> SQL-блок — узкая проверка одного source-паттерна. «Паттерн исчез» не означает
> «все уязвимости исправлены» и не является общим вердиктом. Удаление файла —
> не доказательство исправления.

Не утверждать: «сравнение доказало, что после стало безопасно». Общее сравнение
может остаться `inconclusive`, и это честный результат.

### 7. Отчёт

Действие: открыть «Отчёт» → посмотреть паспорт, AI-слой и Markdown → скачать
официальный JSON или Markdown.

Что видно:

- вердикт и индекс полноты;
- проверено/пропущено файлов, LOC, число правил;
- подтверждённые, потенциальные и неопределённые проблемы;
- предупреждения покрытия;
- статус AI: прошёл валидацию или детерминированный fallback;
- файлы `security-report-….json` и `.md`.

Говорить:

> Отчёт не скрывает неполноту: пропущенные файлы, ошибки парсера и
> неразрешённые зависимости остаются в паспорте.

## Админский путь: backend готов, frontend в разработке

Вход — отдельным `CG_ADMIN_ACCESS_CODE`. Если код не задан или совпадает с
пользовательским, `adminAvailable: false`, а вход администратора возвращает
503. Пользовательский вход при этом работает.

| Раздел целевого frontend | Backend сейчас | Что можно делать | Только просмотр? |
| --- | --- | --- | --- |
| Обзор | `GET /api/admin/overview` | смотреть счётчики, БД, AI, векторные представления, загрузки, workspace, доступ | да |
| Проекты/проверки | API артефактов и проверок | смотреть все артефакты и проверки workspace; TTL и удаление не реализованы | да, факты |
| Сценарии/расписания | API сценариев и расписаний | создавать сценарий и draft, создавать/паузить расписание; удаления нет | частично |
| Анализаторы/покрытие | типы блоков, покрытие в проверке | смотреть реестр блоков и пробелы покрытия; настройки правил не реализованы | да |
| AI/память | статус AI, admin overview | смотреть провайдера, fallback, валидатор, статус векторных представлений; памяти/CRUD нет | да |
| Доступ/система | session, bootstrap, overview | смотреть `adminAvailable`, workspace, health, лимиты; управление аккаунтами отсутствует | да |

`GET /api/admin/overview` — реальный снимок, не декоративная панель:

- счётчики: projects/artifacts, workflows, schedules, schedulesEnabled, runs,
  running, queued, failed;
- БД: bounded `SELECT 1`, latency, migrations;
- AI: provider/model и `configured`, без ключей;
- векторные представления: `enabled`, доступность расширения, версия, `status`,
  реальное число активных спек;
- загрузки: фактические лимиты;
- workspace: `shared: true`, `userAccounts: false`;
- доступ: `publicDemo`, `adminAvailable`.

Секреты, DSN, base URL провайдера и значения кодов в ответ не попадают.

### Матрица прав (реализовано в backend `dev`)

| Действие | user | admin |
| --- | ---: | ---: |
| загрузить ZIP / sample | да | да |
| читать проверки, проблемы, карту, доказательства, отчёт, сравнения | да | да |
| запустить существующий сценарий | да | да |
| валидация и типы блоков | да, только чтение | да |
| создать сценарий / `PUT draft` | 403 | да |
| список / создание / PATCH расписаний | 403 | да |
| AI synthetic-test | 403 | да |
| training artifact | 403 | да |
| webhook-test logs | 403 | да |
| `GET /api/admin/overview` | 403 | да |

Anonymous в публичном режиме на закрытых маршрутах получает 401, `user` на
admin-маршрутах — 403.

Пользовательские разделы: ZIP/демо, выбор сценария проверки, проверка,
проблемы, карта, сравнение, отчёт. Админские: обзор, проекты/проверки,
сценарии/расписания, анализаторы/покрытие, AI/память, доступ/система.

Только просмотр у `user`: проверки, проблемы, карта (факты), отчёт, сравнения.
Только просмотр у `admin`: обзор, проекты/проверки, анализаторы/покрытие,
AI/память, доступ/система.

### Что важно не перепутать

- Роли **уже реализованы в backend `dev`**. Не говорите «ролей нет».
- Админского **frontend** ещё нет в опубликованной сборке. Не показывайте
  выдуманные экраны и не называйте API готовой админкой.
- Роль не создаёт аккаунт и не изолирует данные. Это один общий workspace.
- `admin` может менять сценарии и расписания; `user` — нет.
- Админский обзор только для чтения: он показывает состояние, а не
  управляет им.

## Публичный стенд `9862e19`: только старый путь

На опубликованном стенде пока старая сборка:

- один общий код доступа;
- редактор и `PUT draft`;
- ролей и админки в интерфейсе нет;
- терминология старая: «Находки», «Запуск».

Если показываете именно `9862e19`, используйте короткий старый маршрут:

```text
ZIP/демо → Редактор → Запустить → Находки → Карта → Отчёт
```

Для сравнения нужны две завершённые проверки. Не обещайте на этом стенде
роли, админку и новый простой user-путь: их там нет.

## Что нельзя утверждать

- «Ролей нет» — неверно для backend `dev`: `user`/`admin` реализованы.
- «Есть личные кабинеты, списки доступа, multi-tenant» — нет, общий
  workspace.
- «Админка опубликована» — backend и overview готовы, разделение интерфейса
  ещё в разработке.
- «`pass` значит ноль проблем» — нет: блокирующих проблем нет, низкие и
  допустимые средние могут остаться.
- «Fallback — только когда модель недоступна» — нет: ответ модели может
  отклонить валидатор.
- «Embeddings — это индекс, и он работает» — нет: это векторные представления
  текста; точный поиск без ANN-индекса; реальный запрос вернул 403.
- «Есть проверенные примеры исправлений» — 0; три подготовленных — черновики.
- «Демо-сценарии — это опыт» — это черновики сценариев, не накопленная практика.
- «Публичный стенд уже с новым user-путём» — он на `9862e19`, там старый UI.

## Конкретные правки интерфейса

Это рекомендации, не переделка дизайна.

1. **В целевом UI: «Проблемы», «Проверки», «Сценарий проверки», «Снимок
   проекта».** В старой сборке `9862e19` остаются старые подписи; не смешивайте
   их в одном экране.
2. **Не показывать `user` админские действия.** Редактор, сохранение draft,
   расписания, AI-тест и training уже дают 403. Кнопки должны исчезать, а не
   вести в тупик.
3. **Два сигнала об unknown-связях** (бейдж и баннер) дублируются. Оставить
   баннер с числом и действием, бейдж — только «частичная картина».
4. **Четыре карточки «ФАКТ / ОБЪЯСНЕНИЕ / ВАЛИДАЦИЯ / НЕПОЛНОТА»** в отчёте
   занимают экран. Свернуть в строку статуса AI и `details` с принципами.
5. **Английские статусы в основной строке** (`pass`, `fail`, `confirmed`,
   `fallback`, `partial`). Показывать русский статус, сырой код — в
   «Технических данных».
6. **«Инспектор данных блока» с сырым JSON** открыт всегда. Свернуть JSON под
   «Технические данные», сверху — «что пришло / что ушло».
7. **Не рисовать vector «active» при нуле спек.** В обзоре показывать реальные
   `enabled`, `status`, `activeEmbeddingSpecs`; 0 — это 0.

## Чеклист перед показом

Для целевого user-пути:

- [ ] разделение интерфейса смержено; backend `dev` с ролями.
- [ ] пользовательский код входит как `user`; admin-код не подходит.
- [ ] ZIP/sample загружается; манифест показывает файлы и SHA-256.
- [ ] существующий сценарий запускается **без** `PUT draft`.
- [ ] проблемы, карта, сравнение и отчёт открываются.
- [ ] две завершённые проверки есть для SQL-сравнения.

Для админки:

- [ ] задан отдельный `CG_ADMIN_ACCESS_CODE`; `adminAvailable: true`.
- [ ] admin-вход даёт `role: admin`; overview отвечает 200.
- [ ] user на overview получает 403.

Для публичного стенда `9862e19`:

- [ ] показываем только старый маршрут и старые подписи.
- [ ] не обещаем роли, админку и новый user-путь.
