# Показ прототипа для жюри

Состояние на 21.11.2026. Публичный адрес https://nedra.soloveyka.bond,
опубликованный код `bde900c`, frontend `index-DabRgDEM.js`.
Речь о понимании кейса и сильных фичах: [mentor-defense](mentor-defense.md).

## Путь пользователя: 3–5 минут

1. Войти обычным пользователем. Первый экран — прежняя панель с редактором,
   верхними вкладками и историей.
2. Выбрать сценарий либо создать именованную копию. Добавить блок из палитры,
   изменить настройки в инспекторе, соединить совместимые порты и сохранить.
   Например, выход отчёта подключается к входу report уведомления.
3. Загрузить учебный ZIP или указать публичный GitHub/GitLab. Показать ветку
   и коммит. Для защиты использовать учебные проекты организаторов или свои.
4. Запустить проверку: текущий сценарий сохраняется перед запуском. Показать
   состояния блоков; выполнение и вердикт безопасности — разные вещи.
5. Открыть проблему → замаскированный фрагмент → карту доступа → отчёт.
   Карта отражает факты кода, а не порядок выполнения сценария.
6. На подготовленных before/after показать сравнение. Общее сравнение может
   остаться неопределённым; SQL-блок доказывает только исчезновение конкретного
   паттерна в сопоставимой проверенной области.

История и стартовый результат ограничены выбранным сценарием. Если запусков
нет, показывается пустое состояние, а не результат другого сценария.

## Что выделить

- Собственные анализаторы секретов, зависимостей и Kotlin/Spring-кода.
- Доказательства у находок и связей карты; неизвестные связи видны явно.
- AI объясняет готовые факты, ответ проверяется; при сбое есть fallback.
- Снимок проекта и ревизия сценария закреплены за запуском; история хранится
  в PostgreSQL и не заменяется новой загрузкой.
- Неполное покрытие не выдаётся за полную безопасность.

## Администратор

Отдельный вход и код. Обзор → проекты → сценарий → расписания → результаты →
система. В «Новых коммитах» задать репозиторий и частоту опроса: минимум
60 секунд, по умолчанию 300. При создании запоминается текущий коммит;
скрытого первого анализа нет. Затем показать «Проверить сейчас», паузу и
последний запуск. Это опрос, не мгновенный webhook и не полный CI/CD job.

Пользователь создаёт и сохраняет сценарии, но системные admin API, расписания
и управление наблюдениями доступны только администратору.

## Проверено

- Независимые PG/ASGI: v3→v4, workspace scope, ошибочные URL400, защита
  очереди от потери и повторного фактического старта после истечения lease.
- Независимый живой UI: создание/настройка/связь/сохранение/reload, запуск
  актуальной ревизии и выбранного артефакта, 390/1440, отсутствие admin API
  в user-пути. Найденные mobile clipping и смешивание результата исправлены.
- Публичный API: user/admin200, аноним401, пользовательские admin API403,
  GitLab import200, свой сценарий/revision2, succeeded/inconclusive и report200,
  watch baseline/unchanged/paused, malformed URL400.

Отчёты: [репозитории](reviews/sol-repositories.md),
[редактор](reviews/sol-user-editor.md). История предыдущих выкладок сохранена
в [deployment-final](deployment-final.md).

## Не обещать

Общий workspace без личных кабинетов; только публичные GitHub/GitLab;
покрытие частичное; общее сравнение не доказывает исправление всех проблем;
embeddings/retrieval выключены, проверенных примеров нет; webhook-триггер,
private auth и возврат CI-статуса ещё не реализованы. После падения процесса
уже начатый run автоматически не переигрывается. Это прототип для показа.
