# Сценарий показа для жюри

Короткий проход по текущему продукту и честное разделение состояний. Это не
production-обещание.

Состояние на 21.11.2026.

## Главное за 30 секунд

- Пользователь: выбрать ZIP/пример → запустить готовую проверку → посмотреть
  проблемы, карту, сравнение и отчёт. Без конструктора и `PUT draft`.
- Администратор: отдельный код и группы «Обзор», «Проекты и проверки»,
  «Сценарий», «Результаты», «Система».
- `user`/`admin` — подписанная роль поверх одного общего workspace. Аккаунтов,
  списков доступа и изоляции данных между пользователями нет.
- `pass` — «нет блокирующих проблем по политике», а не ноль проблем и не полная
  проверка. Проблемы ниже порога могут остаться.
- Пока каноническое покрытие частичное, честный не-`fail` — `inconclusive`.
- Общее сравнение `inconclusive`; SQL-проверка узкая; синтетический источник не
  даёт `comparable=true`; проверенных примеров 0.
- Векторные представления текста необязательны, retrieval выключен; сейчас `unavailable` (403);
  точный поиск без ANN-индекса. Активных спек 0, ложного active нет.
- FINAL structure принят: оба остатка AFTER85 закрыты. В проверенных путях
  закрыты все шесть исходных структурных препятствий; полного аудита нет.

## Короткий путь

**Пользователь:** ZIP/пример → Проверка → Проблемы → Фрагмент → Карта →
Сравнение → Отчёт.

**Администратор:** Обзор → Проекты и проверки → Сценарий → Результаты →
Система.

## Пользователь: три шага

### 1. Выбрать проект

Действие: открыть пользовательский экран, загрузить `.zip` или нажать
«Попробовать пример».

Что реально проверяется:

- только `.zip`, до 50 MB;
- защита от path traversal и zip-бомб;
- манифест: имя, SHA-256, размер, число файлов, `.kt` и Gradle-файлов;
- sample — учебный Kotlin/Spring Boot проект с SQL-инъекцией, path traversal,
  command injection и секретами в конфиге.

Пользователь может загружать артефакты и читать их список. Training — только
admin: у `user` `POST /artifacts/sample/training` даёт 403.

Говорить:

> Архив становится артефактом проверки. Дальше анализ идёт по снимку проекта,
> а не по живой папке.

### 2. Запустить проверку

Действие: выбрать готовый **сценарий проверки** и нажать «Запустить проверку».

Чего здесь нет:

- нет редактора графа;
- нет `PUT /workflows/{id}/draft`;
- нет создания сценария, расписаний, AI-теста и training.

Почему: `user` не меняет сценарий. Backend берёт сохранённый draft и его
ревизию, а `POST /workflows/{id}/runs` создаёт проверку по выбранному артефакту.
Если пользовательский экран предлагает «Сохранить draft» — это баг frontend.
Один артефакт авторитетен для проблем, карты, отчёта и публикации; черновик —
только fallback.

Что видно:

- статус выполнения отдельно от вердикта безопасности;
- статусы блоков, длительность, маскированные входы/выходы;
- число проблем и покрытие;
- технические IDs не выводятся в основном пути.

Говорить:

> Пользователь запускает проверку по готовому сценарию. Менять сценарий может
> только администратор.

### 3. Посмотреть результат

Действие: открыть «Проблемы», «Карту доступа», «Сравнить проверки» или «Отчёт».

Что видно:

- вердикт человеческими словами: «Проблем не выявлено в проверенной части»,
  «Нет блокирующих проблем по действующей политике», «Найдены проблемы»,
  «Неполная проверка»;
- проблемы с риском, уверенностью, путём и строкой;
- маскированный фрагмент кода и цепочку;
- карту доступа с unknown-связями и покрытием;
- отчёт с `executionStatus` отдельно от verdict;
- JSON/Markdown для скачивания.

Говорить:

> `pass` не означает «ноль проблем». Это отсутствие блокирующих по политике
> при данном покрытии. Если покрытие неполное, честный вердикт —
> «Неполная проверка».

Не утверждать: «полная проверка», «все уязвимости найдены», «взломали
приложение».

## Карта доступа

Действие: в результате выбрать проблему или узел → «Показать путь».

Что видно:

- узлы: «Актор», «Маршрут», «Guard», «Обработчик», «Операция», «Данные»,
  «Конфиг»;
- связи: маршрут, вызов, передача, чтение/запись, защита;
- счётчики узлов, связей, проблем и доказательств;
- жёлтый пунктир и баннер «Неизвестные или частичные связи»;
- покрытие «полная картина» или «частичная картина».

Говорить:

> Карта — статические факты кода, а не граф выполнения сценария. Жёлтый
> пунктир — пробел анализа, а не безопасное состояние.

Не утверждать: «все связи известны» или «полное покрытие», если есть
unknown/partial.

## Сравнение

Есть два честных варианта.

**Вариант A, если подготовлены две проверки.** Загрузить `before.zip` и
`after.zip` из `examples/demo/sql-before-after/`, выполнить каждую, дождаться
завершения, затем открыть «Сравнить проверки», выбрать «до» и «после» и нажать
«Сравнить».

**Вариант B, если готовых пар нет.** Сравнить две завершённые проверки.
Отдельный блок «Проверка SQL-паттерна» появится только при подходящих данных,
иначе покажет «Отдельная проверка недоступна».

Что видно:

- «Сравнение сопоставимо» или «Недостаточно доказательств: исправление не
  подтверждено»;
- статусы «Остаётся», «Появилась», «Изменилась», «Исправлена», «Не
  подтверждено», «Файл удалён»;
- отдельный SQL-блок: «Паттерн исчез при сопоставимой проверке»;
- синтетический источник никогда не даёт `comparable=true`.

Говорить:

> Общее сравнение остаётся `inconclusive`, пока expected scopes не подтверждены.
> SQL-блок — узкая проверка одного source-паттерна. «Паттерн исчез» не означает
> «все уязвимости исправлены» и не является vetted.

Не утверждать: «сравнение доказало, что после стало безопасно».

## Отчёт

Действие: открыть «Отчёт» → посмотреть паспорт, AI-слой и Markdown → скачать
официальный JSON или Markdown.

Что видно:

- вердикт и каноническую полноту;
- проверено/пропущено файлов, LOC, число правил;
- подтверждённые, потенциальные и неопределённые проблемы;
- предупреждения покрытия;
- статус выполнения отдельно от verdict;
- статус AI: прошёл валидацию или детерминированный fallback;
- файлы `security-report-….json` и `.md`.

Говорить:

> Отчёт не скрывает неполноту: пропущенные файлы, ошибки парсера и
> неразрешённые зависимости остаются в паспорте. `executionStatus` — это
> выполнение, а не вердикт безопасности.

## Админка

Вход — отдельным `CG_ADMIN_ACCESS_CODE`. Если код не задан или совпадает с
пользовательским, `adminAvailable: false`, а вход администратора возвращает
503. Пользовательский вход при этом работает.

| Группа | Что внутри | Что можно делать | Только просмотр? |
| --- | --- | --- | --- |
| Обзор | `GET /api/admin/overview` | смотреть счётчики, БД, AI, векторные представления, загрузки, доступ | да |
| Проекты и проверки | API артефактов и проверок | смотреть проекты и историю, переходить в результаты | да, факты |
| Сценарий | workflows/schedules | конструктор, draft, расписания; удаления нет | частично |
| Результаты | проверки, проблемы, карта, отчёт, сравнение | смотреть результаты выбранной проверки | да |
| Система | анализаторы/покрытие, AI/память, доступ | смотреть фактические данные; настройки правил и память не реализованы | да |

Админский обзор — реальный DTO, не декоративная панель: counts, DB health,
AI provider/model, vector status, uploads, `workspace.shared`, `userAccounts`,
`adminAvailable`. Секреты, DSN, base URL провайдера и значения кодов не
отдаются.

### Матрица прав (локальный `dev`)

| Действие | user | admin |
| --- | ---: | ---: |
| загрузить ZIP / sample | да | да |
| читать проверки, проблемы, карту, доказательства, отчёт, сравнения | да | да |
| запустить существующий сценарий | да | да |
| валидация и типы блоков | да, только чтение | да |
| создать сценарий / `PUT draft` | 403 | да |
| список / создание / PATCH расписаний | 403 | да |
| AI-тест | 403 | да |
| training-проект | 403 | да |
| webhook-test logs | 403 | да |
| `GET /api/admin/overview` | 403 | да |

Anonymous в публичном режиме на закрытых маршрутах получает 401, `user` на
admin-маршрутах — 403.

Пользовательские разделы: ZIP/демо, выбор сценария проверки, проверка,
проблемы, карта, сравнение, отчёт. Админские: обзор, проекты/проверки,
сценарий, результаты, система.

Только просмотр у `user`: проверки, проблемы, карта (факты), отчёт, сравнения.
Только просмотр у `admin`: обзор, проекты/проверки, анализаторы/покрытие,
AI/память, доступ/состояние.

## Что нельзя утверждать

- «Ролей нет» — неверно для локального `dev`: `user`/`admin` реализованы.
- «Публичный стенд уже с user/admin» — он на `9862e19`, там старый UI.
- «Есть аккаунты, списки доступа, multi-tenant» — нет, общий workspace.
- «Public updated» — не заявлен: deploy остановлен и откатан, новая попытка
  pending `007`, public smoke pending.
- «`pass` значит ноль проблем» — нет: блокирующих нет, проблемы ниже порога
  могут остаться.
- «100% полноты значит полную проверку» — нет; смотрите каноническое покрытие
  и причину `inconclusive`.
- «Fallback — только когда модель недоступна» — нет: ответ модели может
  отклонить валидатор.
- «Embeddings — это индекс» — нет: это векторные представления текста для
  точного поиска без ANN; сейчас 403, активных спек 0.
- «Есть проверенные примеры» — vetted-примеров 0; три подготовленных —
  черновики.
- «Общее сравнение доказало исправление» — нет; оно `inconclusive`, SQL-проверка
  узкая.
- «Политика предметной области работает» — нет; она не подключена к канонической
  подписи.
- «Финальная приёмка» — не заявлена: deploy/public smoke и `main` ещё pending.
- «100% полноты» — только при `complete` и подтверждённых scopes; иначе
  «не установлена/недоступна/неизвестна».
